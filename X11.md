# X11 Protocol Contract

This document records LWM's current ICCCM, EWMH, and LWM-specific behavior.
It is the source of truth for external X11 integration. Internal state and
transition ownership belong in [ARCHITECTURE.md](ARCHITECTURE.md).

## Window-manager ownership

LWM selects `SubstructureRedirectMask`, acquires `WM_S0`, refuses to start when
another window manager owns the screen, and broadcasts `MANAGER`. It creates a
supporting window for `_NET_SUPPORTING_WM_CHECK` and identifies it as `lwm`.

## Desktops and root properties

Each monitor has its own workspace set. LWM exposes that model as one flat,
monitor-major EWMH desktop list:

```text
desktop = monitor_index * workspaces_per_monitor + workspace_index
```

`_NET_CURRENT_DESKTOP` represents the focused monitor's current workspace.
Sticky windows use `_NET_WM_DESKTOP = 0xFFFFFFFF` and are visible across the
owning monitor's workspaces.

LWM maintains these root properties:

- `_NET_SUPPORTED`, `_NET_SUPPORTING_WM_CHECK`
- `_NET_CLIENT_LIST`, `_NET_CLIENT_LIST_STACKING`
- `_NET_NUMBER_OF_DESKTOPS`, `_NET_DESKTOP_NAMES`
- `_NET_CURRENT_DESKTOP`, `_NET_DESKTOP_GEOMETRY`, `_NET_DESKTOP_VIEWPORT`
- `_NET_ACTIVE_WINDOW`, `_NET_WORKAREA`, `_NET_SHOWING_DESKTOP`

The client lists include managed desktop and dock windows. Workspace hiding
does not remove a client from either list.

## Classification

LWM uses the first recognized atom in `_NET_WM_WINDOW_TYPE`:

| Type | Treatment |
| --- | --- |
| `DESKTOP` | managed in the Below tier, skipped by focus/taskbar/pager |
| `DOCK` | managed in the Above tier, strut-reserving, skipped by normal focus/taskbar/pager |
| `DIALOG` | managed floating |
| `TOOLBAR`, `MENU`, `SPLASH` | managed floating, skipped by taskbar/pager |
| `UTILITY` | managed floating, above, skipped by taskbar/pager |
| `NORMAL` or unknown | managed tiled; managed floating when transient |
| `DROPDOWN_MENU`, `POPUP_MENU`, `TOOLTIP`, `NOTIFICATION`, `COMBO`, `DND` | mapped directly, otherwise unmanaged |

A transient managed window is skipped by the taskbar and pager. Changes to
`_NET_WM_WINDOW_TYPE` and `WM_TRANSIENT_FOR` reclassify existing tiled and
floating clients, but runtime conversion into desktop, dock, or direct-mapped
popup behavior is ignored. Title and `WM_CLASS` changes update cached metadata
and reevaluate rules; placement/state transitions run only when the effective
rule result changes. Pending named scratchpad claims still respond to late
matching metadata. An unchanged match does not recenter, resize, or rehost a
window after the user has moved it.

Rules can change tiled/floating classification and effective state. See
[config.toml.example](config.toml.example) for rule syntax and current limits.

## State and visibility

The supported EWMH state surface is:

- `_NET_WM_STATE_FULLSCREEN`
- `_NET_WM_STATE_MAXIMIZED_VERT`, `_NET_WM_STATE_MAXIMIZED_HORZ`
- `_NET_WM_STATE_HIDDEN`, `_NET_WM_STATE_STICKY`
- `_NET_WM_STATE_ABOVE`, `_NET_WM_STATE_BELOW`, `_NET_WM_STATE_MODAL`
- `_NET_WM_STATE_SKIP_TASKBAR`, `_NET_WM_STATE_SKIP_PAGER`
- `_NET_WM_STATE_DEMANDS_ATTENTION`
- `_NET_WM_STATE_FOCUSED`

`FOCUSED` is WM-owned; client attempts to change it are ignored. Above and
below are mutually exclusive, modal implies above, and fullscreen supersedes
maximize: entering fullscreen clears both maximize flags, and maximize requests
while fullscreen are ignored. Leaving fullscreen restores normal geometry.
Maximize changes geometry only for floating clients.
Only one visible tiled or floating fullscreen client owns a monitor at a time;
other normal clients there are suppressed except transients of the owner.
`_NET_WM_FULLSCREEN_MONITORS` changes fullscreen geometry, not ownership across
monitors.

LWM writes ICCCM `WM_STATE` as `NormalState`, `IconicState` for an explicit
minimize, and `WithdrawnState` on unmanage. A workspace change moves a client
off-screen without changing `WM_STATE`. Because LWM itself does not unmap
normal managed windows, an `UnmapNotify` is treated as client withdrawal.

At initial manage, `WM_HINTS.initial_state = IconicState` or
`_NET_WM_STATE_HIDDEN` starts a client iconic. Fullscreen geometry is applied
before the first map. Initial maximize is also resolved before mapping; only
floating geometry changes. Adoption of already mapped clients preserves their
current minimized state; it does not reapply `WM_HINTS.initial_state`.

Showing the desktop hides non-sticky tiled and floating clients and clears
focus. Leaving it restores normal visibility, fullscreen ownership, and
fallback focus. Sticky clients remain visible.

## Focus and activation

LWM reads `WM_HINTS.input`, urgency, `WM_TAKE_FOCUS`, `_NET_WM_USER_TIME`, and
`_NET_WM_USER_TIME_WINDOW`. A client is focus-eligible when input is accepted
or `WM_TAKE_FOCUS` is advertised. Missing `WM_HINTS.input` means true. On focus,
LWM sends `WM_TAKE_FOCUS` when supported and also sets X input focus directly.
Runtime changes to `WM_HINTS`, `WM_PROTOCOLS`, and user-time properties are
honored.

For `_NET_ACTIVE_WINDOW`, when another client is active, source `1` application
requests require a nonzero timestamp that is not older than the active
client's known user time. Rejected application requests set
`DEMANDS_ATTENTION`. Source `2` pager/user requests are accepted when the target
is otherwise eligible. No request surfaces a window suppressed by a current
fullscreen owner.

## Client messages and geometry

LWM handles:

- `WM_CHANGE_STATE(IconicState)`
- `_NET_CURRENT_DESKTOP`, `_NET_WM_DESKTOP`
- `_NET_ACTIVE_WINDOW`, `_NET_CLOSE_WINDOW`
- `_NET_WM_STATE`, `_NET_SHOWING_DESKTOP`
- `_NET_MOVERESIZE_WINDOW`, `_NET_WM_MOVERESIZE`
- `_NET_RESTACK_WINDOW`
- `_NET_REQUEST_FRAME_EXTENTS`
- `_NET_WM_FULLSCREEN_MONITORS`

Desktop indices outside the current monitor/workspace graph are ignored. A
missing or sticky desktop hint at initial manage means the focused monitor's
current workspace.

Tiled clients keep layout-owned geometry and receive synthetic
`ConfigureNotify` replies. ConfigureRequests for tiled and floating clients
receive a synthetic acknowledgement even when the resulting rectangle is
unchanged. Floating configure and moveresize requests are
constrained by WM policy; moving a floating window can reassign its monitor.
Floating moveresize requests and pointer drags saturate dimensions to 1..65535
and coordinates to the signed 16-bit range instead of wrapping.
Managed tiled/floating restack requests reapply LWM's global stacking policy.
Requests for unmanaged, desktop, and dock windows are forwarded, after which
LWM reasserts managed ordering.

LWM reads initial and runtime `WM_NORMAL_HINTS` position and size hints for
floating clients. An unanchored position chooses the monitor containing the
hinted center. A transient or EWMH-desktop anchor constrains the target monitor;
an invalid hint falls back to LWM placement. Minimum size, resize increments,
aspect ratio, and gravity are not enforced. Positive size hints above 65535
saturate to the X11 extent limit; nonpositive size hints retain the existing
size. Hints update the normal floating rectangle even while maximized or
fullscreen; presentation remains governed by those states until they are cleared.
A pointer move/resize exits maximize using the currently displayed rectangle as
the starting geometry. Fullscreen windows cannot be interactively dragged.
`_NET_WM_MOVERESIZE` supports pointer movement and all eight resize directions
as defined by [EWMH](https://specifications.freedesktop.org/wm/latest/ar01s04.html).
Resizing fixes the opposite edge while bounding coordinates and extents. The
specified initiating button ends the interaction; zero accepts any release.
A cancel request only ends an interaction for the same window, preserving the
last applied floating rectangle. Keyboard move/resize requests and interactive
requests to start dragging tiled clients remain unsupported. User mouse bindings
can move tiles and resize their splits; resizing a tile away from a split turns
it into a floating client. Losing the dragged client's eligibility releases the
pointer without waiting for another motion or release.

Coordinates saturate to the signed 16-bit range before placement policy
is applied. Oversized dock struts cannot wrap workarea arithmetic.

`_NET_WM_STRUT_PARTIAL` reserves root-relative edge regions with inclusive
coordinate ranges, as specified by [EWMH](https://specifications.freedesktop.org/wm/latest/ar01s05.html).
Each region is projected onto every intersecting monitor, independently of the
dock window's position. Workareas remain rectangular: an intersecting partial
range reserves the corresponding monitor edge. Overlapping reservations use the
largest inset, not their sum. Inverted ranges reserve nothing on that edge.
A complete, correctly typed partial property takes precedence over `_NET_WM_STRUT`,
including when all extents are zero. Missing or malformed partial data falls back
to the four-value legacy property, whose ranges span the root edges.
Frame extents are always zero because LWM does not create decorations.

Scalar window/time hints require a complete, correctly typed 32-bit value;
malformed or truncated hints use the same fallback as absent hints. Window titles
require 8-bit text and retain a bounded 4 KiB prefix. If `_NET_WM_NAME` is absent,
empty, or has the wrong type or format, LWM tries `WM_NAME`, then `Unnamed`.

## WM protocols

When a client supports `WM_DELETE_WINDOW`, LWM sends it on close and sends
`_NET_WM_PING` when supported. It force-kills after five seconds unless a ping
reply cancels the fallback. A client without `WM_DELETE_WINDOW` is killed
immediately.

LWM sends `_NET_WM_SYNC_REQUEST` before WM-driven resize when the client
advertises the protocol and counter. The request is fire-and-forget; layout
does not wait for or time out on the sync counter. Both the one-counter basic
property and two-counter extended property are accepted; LWM uses the first
counter and does not implement extended synchronization.

## Per-window and private properties

For managed windows LWM maintains `_NET_WM_DESKTOP`, `_NET_WM_STATE`,
`_NET_WM_ALLOWED_ACTIONS`, and zero `_NET_FRAME_EXTENTS`. Move and resize are
advertised only for floating clients.

`_LWM_WINDOW_CLASS` is a stable LWM extension containing the UTF-8 value
`tiled`, `floating`, `dock`, or `desktop`. Compositors and other local tools can
use it when `_NET_WM_WINDOW_TYPE` does not distinguish tiled and user-floated
windows.

The root `_LWM_IPC_SOCKET` property contains the active local socket path and
is removed on normal shutdown. `_LWM_RESTART_*` properties are temporary exec
handoff state and are not a public compatibility interface.

`_LWM_RESTART_OWNER` is a private WINDOW/32 handoff marker on the root and the
retained WM window. The replacement WM checks that both identify the same window
and releases that predecessor after claiming root ownership. This prevents an
empty X server from resetting between WM connections without leaking one retained
X client per restart.

## Intentional limits

LWM does not implement window shading, virtual roots, icon publication,
visible-name properties, `WM_COLORMAP_WINDOWS`, session-management protocols,
or system-tray ownership. Popup-only windows are not integrated into workspace,
focus, or stacking policy. LWM is not a compositor.
